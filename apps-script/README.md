# 経費申請アプリ バックエンド（Google Apps Script）

`Code.gs` を Google Apps Script の Web アプリとして公開すると、経費申請アプリの
データを **Google スプレッドシート（データベース）** に、領収書画像を
**Google ドライブ** に保存できます。公開した URL を、経費申請アプリの
ログイン画面（初回だけ表示される「WebアプリURL」欄）に貼り付けて連携します。

## セットアップ手順

1. **スプレッドシートを用意**（任意）
   - 保存先にしたいスプレッドシートを作成し、URL 中の `/d/【ここがID】/edit` の
     ID を控えます。省略した場合は初回実行時に「経費申請データ」という
     スプレッドシートが自動作成されます。

2. **Apps Script プロジェクトを作成**
   - <https://script.google.com> で新規プロジェクトを作成し、
     `Code.gs` の内容を貼り付けます（既定の `Code.gs` を置き換え）。

3. **スクリプトプロパティを設定**（任意）
   - プロジェクトの設定（歯車）> スクリプト プロパティ で以下を追加できます。
     すべて任意です。

     | プロパティ | 説明 |
     | --- | --- |
     | `SPREADSHEET_ID` | 保存先スプレッドシートID。未設定なら初回に「経費申請データ」を自動作成し、IDをこのプロパティへ自動保存して以降再利用 |
     | `DRIVE_FOLDER_ID` | 領収書画像の保存先フォルダID。未設定なら「経費領収書」を自動作成し、同様にIDを自動保存 |
     | `SHARED_TOKEN` | 分析ツール用の読み取りトークン。設定すると GET `?token=<この値>` で全件を読み取り専用取得できる（Looker Studio 等の定期取得用） |
     | `AUTH_SECRET` | セッショントークンの署名鍵（初回に自動生成・自動保存。手動設定不要） |
     | `ANTHROPIC_API_KEY` | 設定するとレシートの**AI解析**（高精度）が有効になる。下記「AIレシート解析」参照 |
     | `OCR_MODEL` | AI解析のモデルID。既定 `claude-opus-5`（最高精度）。コスト重視なら `claude-haiku-4-5` |

4. **Web アプリとしてデプロイ**
   - 右上「デプロイ」>「新しいデプロイ」>「種類：ウェブアプリ」
   - **次のユーザーとして実行**: 自分
   - **アクセスできるユーザー**: 全員（社内限定にする場合は「同じ組織内の全員」）
   - デプロイして表示される **ウェブアプリ URL**（`.../exec` で終わる）を控えます。
   - 初回は権限承認（スプレッドシート・ドライブへのアクセス）を求められます。

5. **アプリに接続して初期設定**
   - 経費申請アプリ（`https://km1121-design.github.io/expense-app/`）を開き、
     「WebアプリURL」欄にウェブアプリ URL を入力してログインを試すと、
     「最初の管理者を作る」画面に切り替わります。
     最初の管理者（表示名・ユーザーID・パスワード）を作成します。
   - 以降は全員ログインが必要になります。管理者が「アカウント」タブで利用者を追加すると
     8桁の利用コードが出ます。「案内文をコピー」して本人に送ってください
     （案内文のリンクを開けば、URLもコードも入力せずにログインできます）。

## コードの更新（手動デプロイ）

`Code.gs` を書き換えたら、Apps Script エディタで貼り替えたうえで
**「デプロイ」>「デプロイを管理」> ✏️（編集）> バージョン「新しいバージョン」> デプロイ**
を実行します。保存だけではウェブアプリに反映されません。

「新しいデプロイ」ではなく既存デプロイの編集にすると、ウェブアプリURL（`.../exec`）が
変わらないため、アプリ側の設定をやり直す必要がありません。

この作業は下記の自動デプロイを設定すると不要になります。

## 自動デプロイ（GitHub Actions・任意）

`main` への push で `apps-script/Code.gs` を Apps Script プロジェクトへ自動反映し、
既存のウェブアプリを新バージョンへ更新できます
（`.github/workflows/deploy-apps-script.yml`）。
**ウェブアプリURL（`.../exec`）は変わらない**ので、アプリ側の設定はそのままです。

設定しなくてもアプリの動作には影響しません（上記の手動デプロイのままになります）。

### なぜ既定が手動なのか

`expense-app/`（画面）は GitHub Pages なので push だけで自動公開されますが、
`apps-script/Code.gs` は **Apps Script プロジェクトのコードの写し**です。
プロジェクトの実体は Google 側にあってリポジトリとは何のつながりもないため、
マージしても Google 側は 1 文字も変わりません。つなぐには Google アカウントの
認証情報を GitHub に預ける必要があるので、既定では手動にしています。

### 手順

1. **Apps Script API を有効化**
   - <https://script.google.com/home/usersettings> で「Google Apps Script API」をオン。

2. **認証情報を作る**（自分のPC等で1回だけ。Node.js が必要）

   ```bash
   npm install -g @google/clasp@3
   clasp login           # ブラウザが開けない環境では clasp login --no-localhost
   ```

   できた `~/.clasprc.json` を、**ファイルから直接クリップボードへ**入れます。
   `cat` の出力を端末で選択してコピーすると、行の折返しや選択範囲のずれで壊れやすく、
   1文字違うだけで JSON として読めなくなるためです。

   | OS | コマンド |
   | --- | --- |
   | macOS | `pbcopy < ~/.clasprc.json` |
   | Windows (PowerShell) | `Get-Content $HOME/.clasprc.json \| Set-Clipboard` |
   | Linux | `xclip -selection clipboard < ~/.clasprc.json`（Wayland は `wl-copy < ~/.clasprc.json`） |

   壊れた状態で登録した場合も、ワークフローが
   「どこが壊れているか」を中身を伏せた形で表示します（トークンはログに出ません）。

3. **IDを2つ調べる**

   | 値 | 調べ方 |
   | --- | --- |
   | スクリプトID | Apps Script エディタ > プロジェクトの設定（歯車）> 「スクリプト ID」 |
   | デプロイID | 「デプロイ」>「デプロイを管理」に表示される `AKfycb...`。ウェブアプリURL `https://script.google.com/macros/s/【ここ】/exec` の中央部分と同じ |

4. **GitHub にシークレットを登録**
   - リポジトリの Settings > Secrets and variables > Actions >「New repository secret」

     | 名前 | 値 |
     | --- | --- |
     | `CLASPRC_JSON` | 手順2でコピーした `~/.clasprc.json` の中身（JSON全文） |
     | `APPS_SCRIPT_ID` | スクリプトID |
     | `APPS_SCRIPT_DEPLOYMENT_ID` | デプロイID（`AKfycb...`） |

5. **試す**
   - Actions タブ >「Deploy Apps Script」>「Run workflow」で手動実行。
   - 成功すれば、以降は `Code.gs` を含む `main` への push で自動実行されます。

### 何をしているか

1. `Code.gs` の構文チェックと回帰テスト（`apps-script/tests/memory.test.js`）。
   失敗したらデプロイしません。
2. `clasp pull` で現在のプロジェクトを丸ごと取得。
3. `apps-script/tools/sync-source.mjs` で **ソースだけ**を差し替える。
   - `appsscript.json`（アクセスできるユーザー・実行するユーザー・タイムゾーン・
     OAuthスコープ）は取得したものをそのまま押し戻すため、公開設定がCIで
     書き換わることはありません。
   - 反映先はプロジェクト側のファイル名に合わせます（日本語ロケールの既定名は
     `コード` で、そこへ別名のファイルを追加すると Apps Script は全ファイルを
     同じスコープに結合するため二重宣言で全体が動かなくなります）。
     プロジェクトのスクリプトファイルは常に1つに保ち、内容の異なるファイルが
     複数ある場合は取り違えを避けて中止します。
4. `clasp push` → `clasp redeploy <デプロイID>` で既存デプロイを新バージョンへ更新。
5. 公開されたウェブアプリへ実際に `status` を投げて**疎通確認**する。
   **失敗したら直前のバージョンへ自動で戻す**（プロジェクトのコードは新しいまま
   なので、原因を直して再実行すればそのまま公開される）。
   - 単体の構文チェックでは、Apps Script が全スクリプトファイルを同じスコープへ
     結合したときにだけ起きる不具合（同じ識別子の二重宣言など）を検出できない。
     実際に動いているデプロイを叩くことでそこまで確かめる。
   - 「アクセスできるユーザー」が全員でない場合は、ログイン画面が返るため
     疎通確認は省略される（デプロイは成功扱い）。

### 注意

- `CLASPRC_JSON` は **そのGoogleアカウントの Apps Script とドライブを操作できる
  認証情報**です。リポジトリを触れる人を信頼できる範囲に限ってください
  （Actions のログ上ではシークレットは自動的にマスクされます）。
- 認証が切れることがあります。`Invalid credentials` 等で失敗したら手順2をやり直して
  `CLASPRC_JSON` を更新してください。
- スクリプトプロパティ（APIキー等）はコードではないため自動化の対象外です。
  従来どおりエディタの「プロジェクトの設定」で設定します。
- 自動デプロイを有効にしたあとにエディタ側で `Code.gs` を直接編集すると、次回の
  自動デプロイで上書きされます。編集はリポジトリ側で行ってください。

## AIレシート解析（オプション・高精度）

レシート画像の読み取りは **AI解析 → 手入力** の2段構えです:

1. **AI解析**（`GEMINI_API_KEY` または `ANTHROPIC_API_KEY` 設定時）。
   金額・日付・店名に加え、**経費科目の自動判定・摘要の自動生成**まで行います。
2. **手入力** — AIキーが未設定のとき、または読み取れなかったとき。
   読み取れなくても、画像を添付したまま申請そのものは進められます。

構造化出力（JSON Schema）を使うため、AIの応答は常に機械可読なJSONです。

### 推奨: Gemini 無料枠（無料で最大精度）

1. <https://aistudio.google.com/apikey> で Gemini API キーを発行（無料）
2. Apps Script のスクリプトプロパティに `GEMINI_API_KEY` として保存
3. （任意）`GEMINI_MODEL` でモデルを固定。未設定なら
   `gemini-flash-latest` → `gemini-3-flash-preview` → `gemini-flash-lite-latest`
   の順に試します。**使えるモデルはAPIキーの種類によって異なる**ため、
   常に現行モデルを指す別名（`-latest`）を先に試します。
   これらが全滅した場合は、そのキーで実際に使えるモデルを自動で調べ直して再試行します
   （モデル名の変更・廃止や無料枠の有無が変わっても設定変更なしで動き続けます）。
   手動で確認したいときは、エディタで `showGeminiModels` を実行するとログに一覧が出ます

無料枠でも経費用途には十分ですが、**1分あたり・1日あたりの上限はモデルと
アカウントによって変わります**（公式ドキュメントも具体値を載せず AI Studio の
[レート上限ページ](https://aistudio.google.com/rate-limit)を見るよう案内しています）。
複数人が同時にレシートを撮る運用で「混雑して解析できません」が続く場合は、
モデルの性能ではなくこのレート上限が原因のことがあるので、そこで確認してください。

**注意: 無料枠は入力/出力がGoogleのモデル改善に利用される**ため、機微データを
学習に使わせたくない場合は有料枠／Vertex AI、または下記 Claude を使ってください。

### 代替: Claude（Anthropic）

1. <https://platform.claude.com> でAPIキーを発行（`sk-ant-...`）
2. スクリプトプロパティに `ANTHROPIC_API_KEY` として保存（`OCR_MODEL` で変更可）

| モデル | 精度 | 概算コスト/枚 | データ学習利用 |
| --- | --- | --- | --- |
| Gemini（既定・自動選択） | 高 | 無料枠内なら0円 | あり（無料枠） |
| Claude `claude-haiku-4-5` | 高 | 約1円 | なし |
| Claude `claude-sonnet-5` | より高い | 約2円 | なし |
| Claude `claude-opus-5`（既定） | 最高 | 約4円 | なし |

コストは1枚あたりの概算（画像1600px・1ドル150円換算）です。

両方のキーを設定した場合は Gemini を優先します（`OCR_PROVIDER` に `claude` を
指定すると Claude 優先）。いずれも未設定の場合は自動入力を行わず、手入力になります。

### 読めなかったときだけ上位モデルへ回す（段階的エスカレーション）

AI解析は**1回目は速度優先**で読み、**金額か日付が取れなかったときだけ**根拠を
厚くして読み直します。既定では読み直しも同じプロバイダなので、**追加の課金は
発生しません**。

難しいレシート（手書き・感熱紙のかすれ・但し書きのみ等）の取りこぼしを減らしたい
場合は、読み直しだけを上位プロバイダへ回せます。

| プロパティ | 値 | 意味 |
| --- | --- | --- |
| `OCR_ESCALATE_PROVIDER` | `claude` / `gemini` | 読み直しに使うプロバイダ。**未設定なら読み直しも同じプロバイダ（課金なし）** |
| `OCR_ESCALATE_MODEL` | 例 `claude-sonnet-5` | 読み直しに使うモデル（未指定ならそのプロバイダの既定） |

例: 普段は Gemini 無料枠、読めなかったレシートだけ Claude へ回す場合

```
GEMINI_API_KEY        = <Geminiのキー>
ANTHROPIC_API_KEY     = <Claudeのキー>
OCR_ESCALATE_PROVIDER = claude
OCR_ESCALATE_MODEL    = claude-sonnet-5
```

**課金されるのは「1回目で読めなかったレシート」の分だけ**です。指定した
プロバイダのAPIキーが無い場合は、設定されていても上位へは回しません
（同じプロバイダで読み直します）。読み直しても読めなければ1回目の結果を
そのまま返し、エラーにはしません（手入力で申請できます）。

## 領収書の保管フォルダ

領収書画像は Google ドライブに次の体系で自動整理されます。

```
経費領収書/
├── <事業部名>/            ← 事業部の追加と同時に自動作成（削除してもフォルダは残る）
│   ├── 2026-07/           ← 月フォルダ（申請時に自動作成）
│   │   ├── 2026-07-15_山田太郎_001.jpg   ← 日付_申請者_採番（同日同者で連番）
│   │   └── 2026-07-15_山田太郎_002.jpg
│   └── 2026-08/
└── 未設定/                ← 事業部なしの申請用
```

**月末の事前生成（任意）**: Apps Script エディタで `setupMonthlyFolderTrigger` を
一度実行すると、毎月28日に翌月分の月フォルダを全事業部へ自動生成するトリガーが
登録されます（初回実行時に権限承認あり）。申請時にも月フォルダは自動作成される
ため、未設定でも運用に支障はありません。

## 認証・権限

- パスワードは「ユーザー」シートにソルト付き SHA-256 ハッシュで保存されます（平文保存なし）。
- ログイン成功で HMAC 署名付きセッショントークン（30日有効）を発行します。起動のたびに、残りが半分を切っていれば新しいトークンへ差し替わるので、使い続けている間は切れません。利用コードの再発行・パスワードの変更・無効化をすると、それ以前のトークンはすべて使えなくなります。
- 権限は `user`（自分の申請のみ・申請/取消）と `admin`（全件閲覧・全件の取消・
  ユーザーと事業部の管理）の2種類。申請者名はサーバー側でセッションから強制されます。
- 利用者は、管理者が発行する **8桁の利用コード**だけでログインします。コードは
  パスワードと同じ列にハッシュで保存されるので、シートを見てもコードは分かりません
  （表示されるのは発行した直後の1回だけ。忘れたら再発行します）。
  コードを再発行すると、パスワードもそのコードに置き換わります。
- 「ユーザー」シートが空の間は認証なしの互換モードで動作します（初期設定前の状態）。

## データ構造（スプレッドシート「経費データ」シート）

1 申請 = 1 行。タブ名と 1 行目の見出しは、シートを直接見る人向けに日本語です。
JSON API・CSV が返すキー名は英語のまま固定なので、分析ツール側の設定は
見出しの日本語化では変わりません。シートの読み書きは列の位置で行っており、
見出しは表示専用です。

| 見出し（1行目） | 内部キー | 内容 |
| --- | --- | --- |
| 申請ID | `id` | アプリが採番 |
| 申請日時 | `createdAt` | ISO8601 |
| 申請者 | `applicant` | 表示名 |
| 利用日 | `date` | 経費発生日 |
| 科目 | `category` | 交通費 / 交際費 など |
| 支払先 | `vendor` | 店名 |
| 金額 | `amount` | 円・数値 |
| 摘要 | `description` | 目的など |
| 状態 | `status` | 常に `approved`（承認の手続きは無い。過去に却下した行は `rejected`） |
| 処理日時 | `reviewedAt` | 申請日時と同じ |
| 処理者 | `reviewer` | 「自動承認」 |
| 却下理由・備考 | `reviewComment` | 過去の行のみ |
| 領収書URL | `imageUrl` | Google ドライブの表示URL |
| 領収書ファイルID | `imageFileId` | 同 ファイルID |
| 申請者ID | `applicantId` | ユーザーID（権限フィルタに使用） |
| 事業部 | `department` | |

この表の右側に、`fareFrom`(出発駅) / `fareTo`(到着駅) / `fareRound`(往復) /
`fareTrips`(回数) / `fareUnit`(片道運賃) / `fareExpected`(想定金額) / `fareCheck`(運賃照合)
の7列があります。かつての運賃照合の列で、**機能は削除したので新しい申請では空**です。
列は位置で読み書きしているため、過去の行と位置をそろえるために残しています。

このほか **ユーザー**（`username, displayName, passwordHash, salt, role, active,
createdAt, department`。`department` は `人材,BAR` のようにカンマ区切りで複数持てます）と
**事業部マスタ** のシートが同じスプレッドシートに作成されます。

> **使われなくなったタブ**
> 過去の版で作られた **運賃マスタ**・**AI学習ログ**・**PL連携マッピング**・
> **PL連携スキップ** のタブは、今のコードは読みも書きもしません。データが残っている
> だけなので、不要なら手で削除してかまいません（残しても害はありません）。
> PL管理モデルへの連携（別スプレッドシートへの反映）は削除したため、PL側に
> すでに入っている行もそのまま残ります。`PL_SPREADSHEET_ID` プロパティも不要です。

> **旧バージョンからの移行**
> 以前の版では、タブ名も見出しも英語（`expenses` / `users` / `departments` /
> `corrections`）でした。新しいコードを再デプロイすると、**次回アクセス時に
> 全シートのタブ名のリネームと見出しの日本語化が自動で行われます**
> （データ行はそのまま）。手動の移行作業は不要です。
> 移行は `SCHEMA_VERSION` プロパティで一度だけ実行されます。
> うまく移行されない場合は、エディタから `migrateSheets` を手動実行してください
> （デプロイ不要）。
> ただし、**タブ名 `expenses` を直接参照している外部連携**
> （Looker Studio のデータソース、他ブックからの `IMPORTRANGE` など）は
> 参照先の再設定が必要です。同じブック内の数式は Google が自動で追従します。

### 領収書画像の共有設定（表示速度に直結します）

領収書画像は保存時に**「リンクを知っている人は閲覧可」**に設定されます。これをしないと、
画像はスクリプト所有者のドライブにあるため所有者以外のブラウザからは表示できず、
アプリが画像1枚ごとにバックエンドへ取得を投げ直すことになって一覧が重くなります。

> **URLを知っていれば、ログインなしで画像を閲覧できる状態になります。**
> ファイルIDは推測できない長さですが、認証はかかりません。この扱いが許容できない
> 場合は `Code.gs` の `shareReceiptFile_` の中身を空にしてください。表示は
> 従来どおりアプリ経由になり（所有者のみに閉じますが遅くなります）、動作はします。

**この機能を入れる前に保存した画像は共有されていません。** エディタで
`shareExistingReceipts` を一度実行すると、既存の画像もまとめて共有設定されます
（デプロイ不要。処理件数がログに出ます）。

### 読み取り精度を上げたいとき

`GEMINI_MODEL` を pro 系にする、`GEMINI_THINKING` を `default` に戻す、
`RECEIPT_RAW_TEXT_MAX_LINES` を増やす、で上がります（いずれも毎回遅くなります）。
読めなかった分だけ上位モデルへ回したい場合は、上記「読めなかったときだけ上位モデルへ
回す」を使ってください。

## API（分析ツール・他システム連携用）

- **GET** `?token=...` → `{ ok:true, records:[...] }`
  - セッショントークン: `user` は自分の申請のみ、`admin` は全件
  - `SHARED_TOKEN` の値: 全件（読み取り専用・分析ツールの定期取得向け）
- **POST**（`Content-Type: text/plain`、本文は JSON。認証系以外は `token` 必須）
  - `{action:"status"}` … 認証が有効か（初期設定済みか）と、バックエンドの版
  - `{action:"setup", username, displayName, password}` … 最初の管理者の作成（初回のみ）
  - `{action:"login", username, password}` / `{action:"loginCode", code}` … ログイン →
    `{token, user}`
  - `{action:"bootstrap", token, month?}` … 起動用。`status`・ログイン中のユーザー・
    事業部・一覧を1往復で返す。`month`（`yyyy-MM`）を付けると、その月の分だけ返す。
    有効期間の残りが半分を切っていれば、新しい `token` も返す
  - `{action:"list", token, month?}` … 一覧（`month` の扱いは同上）
  - `{action:"create", token, record:{...}}` … 申請の作成（`record.imageBase64` が
    あればドライブへ画像保存。申請者はセッションから強制）
  - `{action:"delete", token, id}` … 取消（user は自分の申請だけ、admin は全件。
    画像もゴミ箱へ）
  - `{action:"analyzeReceipt", token, imageBase64, imageMime}` … AIレシート解析
    （`GEMINI_API_KEY` / `ANTHROPIC_API_KEY` 設定時のみ。日付・金額・店名・科目・
    摘要を JSON で返す）
  - `{action:"listUsers", token}` / `{action:"upsertUser", token, user:{...}}` /
    `{action:"issueAccessCode", token, user:{displayName, department, role}}`
    … 利用者の一覧・更新（事業部・有効/無効・パスワード）・利用コードの発行/再発行
    （`user.username` を付けると再発行）（admin のみ）
  - `{action:"addDepartment", token, name}` / `{action:"deleteDepartment", token, name}`
    … 事業部マスタの追加・削除（admin のみ）

## 分析・実績管理への連携例

- **スプレッドシート直接**: 「経費データ」シートをそのままピボット/関数で集計。
- **Looker Studio**: データソースにこのスプレッドシートを指定してダッシュボード化。
- **JSON API**: 上記 GET を BI ツールや自作スクリプトから定期取得。
- **CSV**: スプレッドシートの「ファイル → ダウンロード → CSV」で出力して取り込み。
